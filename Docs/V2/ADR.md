# ADR V2 — decisiones propuestas para aprobación conjunta
| ADR | Decisión | Justificación / límites |
|---|---|---|
| V2-01 | Monorepo incremental: Next.js existente en raíz + API NestJS TypeScript en `backend/`, PostgreSQL 16 + Prisma, Docker Compose. | Mantener despliegue frontend Vercel y API conectable por URL; familiar, modular, sin microservicios extra. Prisma/Nest versiones exactas compatibles con Node 22 y PG16 verificadas en P01/P02, no inventadas. |
| V2-02 | Frontend BFF JSON pequeño same-origin `/api/cms/...` con allowlist explícita; lecturas públicas server-only. | No DB en Next, no secreto público; no proxy abierto, métodos/paths fijos, timeout, body <=1 MiB, no redirecciones externas. Backend sigue autorizando cada operación. |
| V2-03 | Sesión opaca, password Argon2id, cookie HttpOnly, Secure en HTTPS, SameSite=Lax, Path=/, expiración 8h absoluta/30min inactividad. | Sin JWT en localStorage ni registro público. Cookie del BFF, token opaco generado por API y guardado hash en DB; API recibe token únicamente por BFF en header Authorization; no confundir con ticket de upload. CSRF synchronizer token + Origin exacto en mutaciones incluso login/logout. |
| V2-04 | Dominio editorial con draft mutable, snapshot publicado inmutable, versionado optimista, referencias relacionales y auditoría transaccional. | No sobrescribir publicación por edición. Payload JSON tipado por discriminador, validado en backend; relaciones y unicidad con constraints; historial acotado por mantenimiento manual, no purgas automáticas V2. |
| V2-05 | Media en almacenamiento de archivos durable del backend, adapter `MediaStorage`; PostgreSQL metadata, directorios privados, servicio de bytes con checks. | Docker named volume; producción requiere volumen durable con backup, no disco efímero Vercel; S3 opcional futuro, no proveedor contratado. Subida directa al backend con ticket de uso único, preview privado ticket breve; evitar límites de funciones Vercel. |
| V2-06 | Publicación visible en siguiente recarga, `no-store` en admin y lecturas dinámicas; no indexación. | Sin cache invalidation complejo en V2, no modificar políticas SEO sin autorización. Para Cache Components respetar docs instaladas y usar Suspense/runtime boundary; no desactivar globalmente por conveniencia. |
| V2-07 | Importador idempotente de contenido aprobado V1 con IDs estables y provenance, sin fallback en contenido retirado. | Seed demo separado; ausencia real permanece. En indisponibilidad pública mostrar error recuperable/estructura y enlaces aprobados de emergencia solo si explícitamente autorizados; no renderizar estáticos como si fueran estado publicado vigente. |
| V2-08 | Entornos local, CI local equivalente, producción configurable. | Backend/db/volumen no se conectan a producción durante sprint. No Vercel ni hosting nuevo. Pin de Docker images/tag+digest, npm lock reproducible. |
| V2-09 | V2 no modifica fuentes oficiales V1; UI pública cambia solo al integrar capa dinámica. | Frontera por paths y sync final; preservar comportamiento V1, conflictos manuales. |
| V2-10 | Guardar evidencia por patch, runner independiente de Codex, integración fast-forward local, candidato final sin tag. | Control y reanudación; cero falsa evidencia. |

## Diagrama lógico
```
Browser público/OWNER --> Next (grupo público/admin, BFF JSON) --> API Nest --> PostgreSQL
Browser (ticket upload único) -------------------------------> API Media --> volumen durable
Browser (media publicada o preview autorizado) <------------- API Media
```
API interna y URL pública son configuraciones distintas; frontend server-only resuelve `CMS_API_INTERNAL_URL`; `CMS_MEDIA_ORIGIN` HTTPS en producción, localhost local. No CORS wildcard, admitir solo orígenes UI explícitos para upload/preview. Media directa evita 4.5 MB límite tradicional de Vercel Functions y dependencia de beta (referencia https://vercel.com/docs/functions/limitations). Next Cache Components: https://nextjs.org/docs/app/api-reference/config/next-config-js/cacheComponents (leer docs instaladas antes de implementar).

## Versiones y supply chain
Baseline package real está en SPEC. P00 inventario `npm ls --depth=0`, `npm audit --omit=dev`, audit completo, `docker version`, Compose, Node/npm dentro del contenedor. P01 resuelve versiones de registry oficial (npm view engines/peerDependencies/dist.integrity), fija todas las directas exactas en web/backend, mantiene lockfiles; conservar stack existente si compatible y seguro; no major web sin aprobación. Seleccionar Nest + Prisma estables soportados en Node22.19+ y PG16, validar generación/CLI/migrate/build; Node image y Postgres image por versión/digest real; registrar plataformas. Preferir patch/minor compatible; sin `npm audit fix --force`. No actualizar automáticamente después de congelamiento; nuevas dependencias necesarias deben tener versión exacta y motivo por patch. Si un advisory runtime alto/crítico no tiene solución compatible, bloquear release; riesgo dev histórico documentado no se acepta en nombre del propietario. No fijar números de versiones backend inventados. Registrar matriz directa/transitiva crítica, licencias, fecha, origen, motivo y riesgos; reportar `npm ci` limpio y lockfiles sincronizados.
