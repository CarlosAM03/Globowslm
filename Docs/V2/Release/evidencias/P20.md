# P20 — Seguridad y runtime de la candidata

Base `04f67d5c90e2dcf539944578cc7b4ef6b0717858`. Las visitas de documento a `/blog/<slug>` consultan una ruta HEAD pública y acotada antes de emitir HTML. Los artículos inexistentes, no publicados o retirados devuelven HTTP 404 y mantienen noindex. La navegación con el protocolo de Next conserva su vista de no encontrado. La indisponibilidad de la API se trata como indisponibilidad, sin usar un catálogo alternativo.

En HTTPS, Render y Next deben recibir `CMS_BFF_SECRET` desde configuración privada. Este valor solo autentica los dos endpoints de inicio de sesión de Nest. El navegador recibe la cookie opaca y la protección CSRF. `APP_ORIGIN` se valida como origen exacto, `CMS_MEDIA_ORIGIN` se valida para CSP, y `CMS_API_INTERNAL_URL` se resuelve en servidor. La API publica el límite multimedia efectivo bajo autenticación. Nest comprueba el límite al emitir y consumir un ticket. El backend aplica 15 MiB a imágenes, 45 MiB a videos en producción y 100 MiB al perfil Compose local por defecto.

La API usa el `PORT` asignado, escucha en `0.0.0.0` y conserva los endpoints de salud. El proceso de migraciones queda separado. El build excluye la CLI Prisma y TypeScript del runtime porque npm los conservaba como peers opcionales del lock. El pin de ESLint 9.39.5 sigue en QA web por fin de soporte. Las auditorías npm de runtime y árbol completo devolvieron cero hallazgos. Las dependencias directas y sus lockfiles conservan su versión.
