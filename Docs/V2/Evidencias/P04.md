# P04 — Autenticación y BFF seguro

- R01/R11. Base `fde9bc9c9ec800c0938c05093d2abe4eb9175e48`, rama `patch/v2/P04`. NestJS, PostgreSQL 16.16 y Next 16.4.6 en Docker Compose local.
- Migración de OWNER único, sesiones, desafíos de login y límites. CLI `provision` y `recover`, Argon2id, hashes de tokens y rotación. La recuperación revoca sesiones. La sesión tiene expiración absoluta de 8 horas e inactividad de 30 minutos. El guard protege las rutas por defecto, con salud y desafío/ingreso explícitamente públicos.
- El BFF admite cuatro combinaciones de método y destino. Tiene límite JSON de 1 MiB, timeout de 5 s, rechaza redirecciones y valida el origen POST. Un desafío de un uso en PostgreSQL y su cookie HttpOnly protegen el ingreso. La respuesta browser expone OWNER y CSRF, y el token de sesión queda en la cookie. El backend exige bearer y comprueba origen y CSRF en logout.
- Se movieron los componentes públicos al grupo público sin cambiar la landing. La ruta `/admin` requiere sesión y usa un límite de ejecución de Next con `connection()` y Suspense. CSP conserva las políticas de V1 y permite formularios del mismo origen en admin y BFF. El login y el BFF responden sin caché.
- Gate preliminar de API: generación Prisma, migración desde cero, tipos, lint y build correctos. 6 unitarias y 9 integraciones pasaron, incluyendo CLI de provisión/recuperación, hash Argon2id, cuenta única, sesión directa sin bearer, sesión revocada/expirada, bloqueo en el sexto intento, origen incorrecto y repetición CSRF. El límite toma el socket, así que clientes detrás del mismo BFF comparten la cuota por IP.
- En `globows-v2-p04-ui`, se arrancó la API y se ejecutó `playwright test --config tests/auth-live/playwright.config.ts` dentro de `web-qa`, con la cuenta generada para ese proyecto. 1 prueba Chromium aprobada en 15,5 s. Confirmó error en login inválido, login correcto, acceso al panel, atributos HttpOnly/SameSite=Lax/Path=/ en HTTP local, token ausente del JSON, origen/CSRF incorrectos rechazados y logout efectivo. La cookie usa Secure al configurar HTTPS. La corrida preliminar usó loopback HTTP.
- Correcciones de las dos corridas previas de Chromium: se evitó enviar antes de que el formulario se hidrate. Se fijó el límite explícito de tiempo de petición antes de generar el ID de solicitud y se comprobó el cuerpo de la respuesta con el cliente HTTP de Playwright para evitar perderlo durante la navegación. El gate web estándar conserva las 29 E2E de V1 y añade la entrada anónima al admin.
- `@node-rs/argon2@2.2.2` (MIT) está fijado en el lock. La resolución npm reportó cero hallazgos. Los logs conservan ID y estado, sin contraseñas ni tokens.
