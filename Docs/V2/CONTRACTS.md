# Modelo de dominio y API — contrato implementable
Los nombres físicos pueden adaptarse a convenciones Prisma sin cambiar semántica. IDs UUID, tiempos UTC, transacciones PostgreSQL, migraciones versionadas (no db push como despliegue), FK restrict para referencias, índices de consulta y unicidad de slug por tipo. No almacenar media base64 en DB.

## Modelo mínimo
- `Owner(id,emailNormalized unique,passwordHash,active,createdAt,updatedAt)`; `Session(id,tokenHash unique,ownerId,createdAt,lastSeenAt,expiresAt,revokedAt,csrfHash)`; nunca devolver hash/token salvo token inicial por canal BFF privado. Rate limit por identidad/IP con almacenamiento DB o mecanismo durable por instancia documentado (login 5 intentos/15 min por combinación + límite IP; no confiar X-Forwarded-For sin proxy confiable). Provisión CLI interactiva/env efímero, sin password por argumento ni fixtures prod.
- `ContentEntry(id,kind,slug,position,version,draftPayload JSONB,createdAt,updatedAt,archivedAt,publishedRevisionId nullable,sourceKey nullable unique)`. `Revision(id,entryId,revisionNo,payload JSONB,slug,position,publishedAt,actorId)`, unique(entryId,revisionNo). Draft refs y revision refs en tablas separadas con FK (`DraftMediaRef`, `RevisionMediaRef`, `DraftEntryRef`, `RevisionEntryRef`) y roles/orden; o equivalente transaccional. `publishedRevisionId` debe pertenecer a la misma entrada, estado derivado con `withdrawnAt` y archive. No devolver historial por API pública. Version optimistic CAS en cada mutación; devolver 409 con versión actual no contenido secreto.
- `Media(id,storageKey unique,originalName safe,mime,size,sha256,width,height,duration nullable,alt,title,status,createdAt,updatedAt,version)`; estados STAGED/READY/RETIRED/DELETING según necesidad, no publicar STAGED. `UploadTicket(tokenHash,ownerId,sessionId,expectedMime,maxBytes,expiresAt,usedAt)`; `AuditEvent(id,actorId,action,entityType,entityId,requestId,at,changedFields,outcome)` sin secretos/PII innecesaria. Auditar operaciones exitosas en transacción y fallos de seguridad en log sanitizado. `ImportRecord(sourceKey,sourceHash,entryId,lastImportedAt)` para importación sin sobreescribir edición editorial. No extraer user emails a público.

## Payloads (DTOs discriminados, rechazo de campos desconocidos, validación referencial)
| kind | Campos mínimos y opcionales |
|---|---|
| SITE singleton | brandName, founderName, hero title/subtitle/photoRef, about title/history/philosophy/portraitRef, trajectory, contact channels, FAQ lista Q/A validada, seo title/description; CTA WhatsApp contextual; optional según V1. |
| SERVICE | title, description, imageRef opcional en draft, eventTypes refs opcionales, ctaInterest enum compatible con helper actual; imagen requerida para nuevas publicaciones salvo dato heredado documentado sin imagen. |
| EVENT_TYPE | title, description?, imageRef?; solo catálogo, no eventos agendados. |
| GALLERY_CATEGORY | title, description? |
| GALLERY | title, categoryRef, orderedPhotoRefs[] con alt/caption, featured boolean; fotos READY; publicación mínima una. |
| TRAINING | title, description, trainingType COURSE/WORKSHOP/ADVICE/CERTIFICATION (solo oferta presencial), photoRef?, videoRef?, ctaInterest; sin fechas de agenda ni inscripción. |
| CERTIFICATION | title, issuer, date? (YYYY-MM-DD), description?, evidenceMediaRefs[], verified boolean; publicar requiere verified y issuer/title. |
| BLOG_CATEGORY | title, description? |
| POST | title, excerpt, slug, ordered blocks de párrafo/heading/list/media(image/video), coverRef?, categoryRefs[], tags[]; fecha publicación calculada por servidor, autor editorial de marca. |

Límites iniciales aprobables: título 160 caracteres, slug 100 ASCII lowercase, excerpt 300, descripción 4000, bloques hasta 100 y texto de bloque 5000, listas 50 ítems, alt 300, tags 10 de 50, gallery 100 refs, paginación default 20/max 100. Contacto: HTTPS y dominio esperado para redes; email válido o ausente; teléfono/WhatsApp número normalizado y conservación de destino aprobado hasta cambio expreso de propietaria. Rechazar `javascript:`, `data:` y enlaces no permitidos; no HTML raw. Validar tamaño total JSON <=1MiB, ningún campo arbitrario. Versiones integer positivas, orden >=0. Incluir UI mensajes útiles en español, error estable máquina/fieldErrors. Probar concurrencia y rollback transaccional.

## API REST /api/v1 (OpenAPI real versionado y validado)
- GET `/health/live`, `/health/ready` (ready DB+storage, sin detalles sensibles).
- POST `/auth/login`, POST `/auth/logout`, GET `/auth/session` (devuelve owner público + CSRF para BFF); GET sesión no almacenable, POST login requiere Origin/CSRF prelogin en BFF; session rotation al login; invalidación al rotar password. BFF administra cookie no expone sessionToken a JS; API protegida con `Authorization: Bearer <opaque-session>` desde BFF. No credencial API pública adicional necesaria; backend comprueba sesión y CSRF validado por BFF + token para mutaciones, endpoints directos no deben aceptar cookies ni CORS para operaciones admin normales.
- GET `/admin/dashboard`; GET/POST `/admin/content/:kind`; GET/PATCH `/admin/content/:kind/:id`; POST `.../:id/publish`, `/withdraw`, `/archive`, `/restore`; GET `.../:id/preview`; GET `.../:id/revisions` (metadata/detalle admin). IDs y kind allowlist; version requerida; payload específico por kind; 201 alta, 200 actualización, 400/422 inválido, 401 anónimo, 403 CSRF, 404 ausente, 409 conflicto/ref, 413 tamaño, 429 límite. Dashboard real por tipo/estado, historial paginado; no mutations GET.
- GET `/admin/media` paginado; GET/PATCH `/admin/media/:id` (version); POST `/admin/media/upload-ticket` (mime, size); POST `/media/upload` ticket bearer de un solo uso, binario streaming directo browser (no BFF); POST `/admin/media/:id/preview-ticket`; GET `/media/preview/:id` ticket de lectura corto, no-store, no-referrer, no logs query; DELETE `/admin/media/:id` solo sin referencias; `GET /media/public/:id` y HEAD únicamente READY + referencia en snapshot publicado vigente. Rechazar traversal/IDs no válidos. Range de video 206 y 416 correcto. Media pública `Cache-Control: no-store` inicial para retirada inmediata, ETag opcional; nunca servir staging por URL pública. Sin redirects a host arbitrario. Ticket expiración 5min, hash, uso único transaccional; límite imagen 15 MiB/video 100 MiB; CORS exacto para subida; streaming con límite efectivo y comprobación de magic bytes/decodificación imagen, firma/contenedor de video y MIME, no SVG/HTML/ejecutables; validación de dimensión/píxeles (40MP máx), metadatos seguros, tamaño, extensión no confiable. Guardar temporal, rename atómico, compensar si DB falla; limpieza huérfanos con CLI dry-run, nunca cron destructivo. Media privada preview por ticket corto (no reuse fuera de alcance); evitar URL con token persistente en logs.
- GET `/public/site` devuelve agregación institucional + catálogos publicados (arrays ordenados, refs resueltas a DTO públicos, sin hashes/version draft); GET `/public/posts?page=...&category=...`, GET `/public/posts/:slug`. Si no publicado, 404; vacío válido no es error. Publicación sólo cuando refs y media elegibles; si dependencia se retira, bloquear si aún publicada. Media URLs construidas con origen configurado, sin URLs de storage internas.
- Error estándar `{code,message,requestId,fieldErrors?}`; sin stack trace externo. Request ID generado/validado; logs JSON sanitizados; timeout BFF, 503 cuando upstream caído. Paginación `{items,page,pageSize,total}`. No cachear respuesta autenticada; no forward de headers arbitrarios/Set-Cookie de API al browser, BFF emite cookie propia. OpenAPI debe describir esquemas/errores y seguridad; pruebas de contrato frontend/backend.

## Layout / migración / publicación
Mover navbar/footer/floating desde root layout a `(public)/layout.tsx` sin alterar anchors; root solo fonts y HTML; admin layout protegido. Conservar D01–D09 y FAQ condicional, assets originales. Blog usa enlaces públicos hacia `/` con anclas; ajustar navegación fuera de landing. Contenido estático V1 se convierte en fixture de importación comercial con hash y fuente, no fallback para retiradas. `import:v1 --dry-run` imprime plan sin secretos; `--apply` transaccional e idempotente, nueva publicación solo si sin conflicto; hash cambiado y edición CMS => reporte conflicto, no overwrite. Archivos de imagen aprobados se copian por checksum sin modificar originales. Demo `seed:demo` solo modo local/test explícito, nunca se activa por producción ni se mezcla con catálogo aprobado; nombre fixture inequívoco. Bootstrap de producción manual y verificable; migraciones y backups antes de conectar.
